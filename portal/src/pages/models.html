What to know first. One file, models/dq-capability.yaml, holds the whole model. Every download below is generated from it, so they always agree. The model follows GOV.UK guidance as published (see the guidance key); it is a starting point for your organisation to adapt, not an official government model. The Visio file was checked by opening it in LibreOffice; tell us through the contact form if your Visio version shows it differently.

Capability map, overlaid with the Government Data Quality Framework

Twelve capabilities make up end-to-end data quality management. Each one's colour shows the framework principle it mainly serves; the codes show the guidance it puts into practice.

Visio process map

Eight pages: the capability map, the five workflows as swimlane diagrams, the information model and the guidance key. Every shape carries its guidance and records as shape data, so you can report on them in Visio. Visio file (.vsdx) · PDF for anyone without Visio.

The same content is written out in full under Workflows for people using screen readers or small screens.

Workflows

Five workflows carry out the capability. Each is a BPMN 2.0 file with its diagram layout, so process tools draw it the same way. Steps marked "automated" run in the Commons toolkit or a scheduled job.

Information model

The records the capability keeps. Names of people are not part of the model: roles are held as role holders and contact routes are forms, in line with the privacy notice. Entity relationship diagram (SVG) · data dictionary (CSV).

How to import

  1. Archi (free): File, Import, Open Exchange XML Model, then choose archimate/dq-capability.xml. Or File, Import, CSV Data Into Selected Model, then choose dq-elements.csv (the relations and properties files are read with it).
  2. Sparx Enterprise Architect: for ArchiMate, Publish, Model Exchange, ArchiMate Exchange Format, Import. For the class model, Publish, Import, XMI, then choose uml/dq-data-model.xmi.
  3. BiZZdesign, ADOIT, ARIS and other ArchiMate tools: use their Open Exchange Format import with archimate/dq-capability.xml.
  4. Visio: open visio/dq-capability-process-map.vsdx. To see the guidance on a shape, right-click it and choose Data, Shape Data.
  5. Camunda Modeler, bpmn.io, Signavio, Bizagi: open or import any file in bpmn/.
  6. A database: run sql/dq-data-model.sql in PostgreSQL, or reverse-engineer it in erwin, ER/Studio or DBeaver.
  7. Protégé or a knowledge graph: open rdf/dq-data-model.ttl.
  8. A catalogue or spreadsheet: open dictionary/data-dictionary.csv; most catalogues (for example Purview, Collibra, DataHub) can load it as a business glossary or attribute list.

Change the model

  1. Suggest a change with the contact form, or edit models/dq-capability.yaml on GitHub and propose it.
  2. Whoever looks after the repository runs python3 scripts/build_models.py, which rebuilds every file above.
  3. The automated checks fail if any download no longer matches the YAML, so the files can't drift apart.
