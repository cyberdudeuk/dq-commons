What to know first. One file, models/dq-capability.yaml, holds the whole model; every view and download here is made from it, so they always agree. It follows GOV.UK guidance as published (see the guidance key). It is a starting point to adapt, not an official government model.

Workflows

Five workflows carry out the capability. Press Play to walk through the main path, or choose any step. Highlight a role to see only that role's steps. Each step says where to do it in the Commons.

    Coloured boxes are steps (colour = framework principle; ⚙ = automated). Diamonds are decisions. Green circle: start. Red circle: end. Use Tab to move between steps, Enter to choose one, and the left and right arrow keys to step through.

    How to import

    1. Archi (free): File, Import, Open Exchange XML Model, then choose archimate/dq-capability.xml. Or File, Import, CSV Data Into Selected Model, then choose dq-elements.csv.
    2. Sparx Enterprise Architect: for ArchiMate, Publish, Model Exchange, ArchiMate Exchange Format, Import. For the class model, Publish, Import, XMI, then choose uml/dq-data-model.xmi.
    3. BiZZdesign, ADOIT, ARIS and other ArchiMate tools: use their Open Exchange Format import.
    4. Visio: open the .vsdx file. To see a shape's guidance, right-click it and choose Data, Shape Data.
    5. Camunda Modeler, bpmn.io, Signavio, Bizagi: open or import any file in bpmn/.
    6. A database: run sql/dq-data-model.sql in PostgreSQL, or reverse-engineer it in erwin, ER/Studio or DBeaver.
    7. Protégé or a knowledge graph: open rdf/dq-data-model.ttl.
    8. A catalogue or spreadsheet: open dictionary/data-dictionary.csv.

    Change the model

    1. Suggest a change with the contact form, or edit models/dq-capability.yaml on GitHub and propose it.
    2. Whoever looks after the repository runs python3 scripts/build_models.py, which rebuilds every file and this page.
    3. The automated checks fail if any download no longer matches the model, or if a link to a page, playbook stage or role is broken.
