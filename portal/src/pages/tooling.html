How does the public sector check its data quality, and what does its open code show?

A scan of data quality (DQ) frameworks and tools used across government, plus a read of 27 public GitHub repositories from 14 public sector organisations. It looks at which tools, quality dimensions and standards appear in real code, and what that means for reporting quality on critical data assets (CDAs) and bringing them into the National Data Library (NDL).

What the evidence shows

Finding 1

Teams build their own rule engines

The strongest tools are domain-specific: the Home Office profiler (169 rule modules on Spark), the DfE open data screener (63 checks), and the planning data pipeline's YAML expectations engine. General frameworks are almost absent from public code.

Finding 2

Planning data has the most mature model

MHCLG's specification maps 45 issue types to a quality dimension, a severity level and who must fix it (internal or data provider). It also defines a 7-step quality ladder from "no data" to "trustworthy". This is a ready-made pattern for CDA issue logs.

Finding 3

Quality is missing from the metadata model

The cross-government metadata exchange model (LinkML, DCAT-based, outputs JSON Schema and SHACL) has no quality properties. A CDA's baseline scores can't be exchanged in a machine-readable way today.

Finding 4

The dimensions are uneven

Uniqueness, validity and accuracy show up most in code. Timeliness is the least covered (6 of 21 repos), and none of the 45 planning issue types measures it. The six DAMA UK dimensions are named explicitly only in guidance repos.

Finding 5

The central data quality community has gone quiet

The DQ Hub's resources repo is nearly empty and was last updated in 2022. The admin data quality framework stopped in 2023, and the question bank in 2024. Two once-public MoJ validation tools (data_linter, mojap-metadata) can no longer be reached.

Finding 6

Inclusion checks are rare

Only DfE's screener enforces GSS harmonised ethnicity values, and only NHS England's linkage framework tests for uneven error across population groups. No repo reports completeness of protected-characteristic fields separately.

Limits of this scan. GitHub's code search needs a sign-in, which this session doesn't have, so repos were found by name and description and then read in full. Private repos and commercial platform configurations are invisible. Some tool use inside large repos may be missed.

Standards: used, partly used, missing

Used

  • DAMA UK six dimensions, through the Government Data Quality Framework
  • DCAT, in the metadata exchange model and planning specification
  • LinkML to JSON Schema and SHACL (CDDO)
  • GSS harmonised standards (DfE)
  • CSVW (planning data)

Partly used

  • QAAD, in analysis guidance only
  • ESS validation and VTL, through R validate (international)
  • Frictionless table schema, mentioned but not enforced
  • ISO 8000 and ISO/IEC 25012, in 2 repos as references only

Missing

  • W3C Data Quality Vocabulary (DQV), for publishing quality results as metadata
  • A shared issue-type vocabulary across departments
  • Machine-readable DQAP results
  • Representativeness and inclusion measures
