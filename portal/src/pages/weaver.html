Application profiles

Does the DCAT output meet each profile? Must properties are required; should properties are recommended. These are simplified shapes that catch the common gaps: check against the official SHACL shapes (from SEMIC for the European profiles) before you publish. The UK profile uses the critical data asset properties from the GOV.UK metadata guidance, including its allowed values for access rights and classification. The UK GEMINI check lists what a geospatial record still needs (for example lineage, recorded as dct:provenance): for full GEMINI XML use your GIS catalogue.

3. Fill the gaps

Edit any field and the outputs update. Lists take commas. Distributions take one per line: title | url | format. Each field is mapped through the Metadata Rosetta.

Contract change check

Before you publish a new version of an ODCS data contract, check it, and compare it with the last version. The check lists changes that would break the people who use your data, and the version number to use.

Run it yourself

The Weaver is part of the open toolkit (MIT licence). Use it in your own catalogue, pipeline or AI agent, with no dependency on this site.

Command line

python -m dqkit weave record.json --report
python -m dqkit weave record.json --to dcat
python -m dqkit contract-check new.yaml --against old.yaml

Python

from dqkit import weaver, contracts
w = weaver.weave(record)
w["outputs"]["dcat"], w["cda"]["coverage"]
contracts.diff_odcs(old, new)

AI agents (MCP)

Why a weaver, not just a crosswalk

Our assessment

A crosswalk tells you that dct:title and name mean the same thing. Teams still have to retype records for each catalogue, and gaps only show up after publishing. A weaver does the translation, keeps one source of truth, and shows gaps before anything goes live.

  • Worth building: the same dataset is often described in data.gov.uk (CKAN), a department catalogue (DCAT), web pages (schema.org) and a data contract (ODCS). Each copy drifts.
  • Safe to share: it's deterministic, open and runs offline, so any organisation can replicate it, including Crown Dependencies, Overseas Territories and partners abroad.
  • Honest: nothing is invented. Missing fields stay missing and are reported. Fields a standard can't carry are listed as "not carried".
  • Since version 2.1: CSVW and Frictionless inputs, GeoDCAT-AP and StatDCAT-AP outputs, and profile checks for DCAT-AP, GeoDCAT-AP, StatDCAT-AP and the UK critical data asset properties. Since version 2.12: a concept-by-concept mapping of the Weaver to the UK cross-government Metadata Exchange Model, DCAT and DQV, ready for review: download the mapping (CSV). It becomes the Weaver's UK profile once the Data Standards Authority's peer review route has checked it.
