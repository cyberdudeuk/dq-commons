How does government data quality guidance fit together, and where does it disagree?

Fifteen sources compared. Nine are guidance documents: the 2026 GOV.UK guidance, the DQAP Implementation Guide v2.0, the Issues Framework v1.0, Defra's "Start here", the IOPC trust scales, a 2023 decision tree, NHS England's framework for data science and the community note. Six are tooling and adoption material: GDS's tooling review, solutions survey and case study template, two DQAP adoption decks, and a brief tools research note. Each step is mapped to the open data quality kit that puts it into practice.

Evidence base. This page compares UK government data quality guidance in detail and holds the issues framework calculator. For frameworks across all nations, sectors and countries, see Frameworks and standards.

Contradictions and errors found

#FindingWhy it mattersSeverityHow the kit handles it

F1 drawn to scale: bands for a 97.5% target

The rule says the High band starts halfway between the Middle band start (95%) and the target (97.5%), which is 96.25%. The v1.0 table prints 96.75%. Under the printed figure, a result of 96.5% falls in the Middle band, scoring 2 instead of 1. That doubles its priority score.

What each source adds

Defra "Start here"

The smallest workable DQAP. Estimates are allowed at first. This supports a proportionate January baseline for critical data assets.

IOPC trust scales

Turns quality into a usage decision: internal only, or external. Personal data accuracy below 90% can't be rated Trustworthy. Built into the kit's trust level.

Decision tree (2023)

The only source covering data you receive but don't control. That is common for shared critical data assets and for the NDL. Built into the kit's DQAP route.

NHS England framework

Covers the quality of the analysis built on data: commissioning, peer review, version control and uncertainty. It complements the DQAP.

Community guidance note

Already lists the W3C Data Quality Vocabulary as future metadata guidance. It records organisations' practice too: risk-based critical data elements, a 10-step remediation process, and shared tooling.

Built into the kit from the tooling and adoption material (v0.3.0)

Recommendations

  1. Correct Issues Framework v1.0 Tables 7 and 8, and clarify the band labels (F1, F2), wherever the tables are still used.
  2. Use one numbering for DQAP steps, and rename ESDA templates to critical data asset templates (F3, F4).
  3. Add a trust level to critical data asset guidance and metadata, so quality decides how data may be shared (F6).
  4. Add an external-data route to the DQAP guide, based on the decision tree (F7).
  5. Expect representativeness checks for critical data assets that hold personal data (F8).
  6. Offer Defra's "Start here" as the official proportionate entry point for the January baseline.
  7. Fix the survey before launch: privacy notice, organisation type and size, CDA links, Data Maturity Assessment levels, consistent ratings (F12, F13).
  8. Widen the tooling review to open-source and government-built tools, with criteria for accessibility, open standards and exit (F10, F11).
  9. Add before-and-after measures, a CDA identifier and inclusion to the case study template (F15).
  10. Publish the Shared Learning Library openly and catalogue it in the NDL (F17).
  11. Put issue ageing, escalation and containment versus corrective action into the GOV.UK DQAP guide, and correct the deck errors (F16).
