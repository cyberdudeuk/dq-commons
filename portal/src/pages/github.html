Everything you see in this portal is built from files kept in one open, public place on GitHub. You don't need to code to use it. This page explains what GitHub is, why the Commons uses it, and what you can do there at each level of confidence.

What GitHub is

GitHub is a website for keeping files that many people work on together. Think of it as a shared folder that remembers every change ever made, who made it and why, with a noticeboard attached where anyone can raise a problem or suggest an improvement. A project's folder on GitHub is called a repository (or "repo").

The Commons repository is github.com/cyberdudeuk/dq-commons. It is public, so anyone can read it, and free to reuse: code under the MIT licence and content under the Open Government Licence.

Why the Commons uses it

  • Open by default. Anyone can see how checks work and where every claim comes from, which builds trust. This follows the Service Standard on making source code open.
  • A full history. Every version is kept, so nothing is lost and any change can be traced or undone.
  • Everyone can contribute. Report a problem or suggest a change through a simple form, without installing anything.
  • Checks run automatically. Every change is tested for errors, accessibility and broken links before it reaches the portal.
  • Free to reuse. Any organisation can take a copy and adapt it, with nothing locked in.

Background, aims and desired outcomes of the Commons itself are on About the Commons.

What you can do, by level

Beginner no account needed

  • Read any file and its history in your browser.
  • Download a release as a zip file to keep or share.
  • Use everything in this portal; none of it needs GitHub.

Intermediate free GitHub account

  • Report a problem or ask for a feature with a short form (an issue).
  • Join a conversation in Discussions.
  • Suggest a wording fix straight in your browser (a pull request).
  • Watch the repository to hear about new releases.

Advanced some technical confidence

  • Run the toolkit on your own computer (see the README).
  • Add rules, framework packs or code, with tests.
  • Take your own copy (a fork) to adapt for your organisation.
  • Read CONTRIBUTING.md and the architecture notes.

Step by step

Report a problem or idea

  1. Sign in to GitHub (creating an account is free).
  2. Go to New issue.
  3. Choose the form that fits: bug, feature, rule or pack, or contribution.
  4. Fill in the boxes in plain words. Leave out names and personal details.
  5. Select Create. You'll get updates as it is worked on.

Suggest a wording change

  1. Open the file you want to change on GitHub.
  2. Select the pencil icon, "Edit this file". GitHub makes your own copy for you.
  3. Make the change, then write one line saying what you changed and why.
  4. Select Propose changes, then Create pull request.
  5. A maintainer reviews it; the automatic checks run; once merged it goes live.

GitHub's own guide is a good next step: Hello World (about 10 minutes).

Key words

Repository (repo)
The project's folder of files and their full history.
Commit
One saved change, with a note saying what changed and why.
Branch
A separate line of work, so changes can be tried without affecting the live version.
Pull request
A proposal to bring a change into the main version, with room for review and discussion.
Issue
A numbered report of a problem, question or idea, with its conversation.
Fork
Your own copy of someone else's repository, to adapt or to propose changes from.
Release and tag
A named, numbered version (for example v2.0.0) you can download and refer to.
GitHub Actions
Automatic jobs that test, check and publish the work on every change.
GitHub Pages
GitHub's free website hosting, which serves this portal.
Dependabot
An automatic helper that proposes updates when tools the Commons relies on change.

Find other public sector code

The Commons is one of thousands of public sector projects on GitHub. The GitHub Repos Asset Catalogue lists every UK public sector code project, organised by topic, organisation, question and capability, and explained in plain English for people who don't use GitHub. Search it for "data quality" to find checks, validators and dashboards other teams have already built, and reuse them before building your own.

The catalogue and the Commons share an approach: open by default, plain English at three levels, contact by form only, and automatic checks that keep personal data and credentials out of the repository.

Staying safe in a public space

  • Everything on GitHub here is public. Never post personal data, real records, passwords or anything marked OFFICIAL-SENSITIVE.
  • Use made-up example data when you report a problem with a check.
  • Report a security problem privately, as described in the security policy, not as a public issue.
  • The code of conduct applies everywhere.
  • Prefer not to use GitHub? Every route has an alternative: see getting help, or ask a colleague to send the contact form for you.
