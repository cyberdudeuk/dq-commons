From request to release

  1. RequestAnyone raises it: wishlist, a GitHub form, a commission or the contact form.
  2. Weekly triage30 minutes, open notes. Each item is labelled backlog, answered, community, specialist or declined (with the reason).
  3. BacklogEach backlog item is a GitHub issue, placed in the Now, Next, Later or Done milestone automatically, the same stages as the portal's roadmap. With Jira connected, the backlog label also creates a Jira story and comments its key back.
  4. PrioritiseMonthly: user value × reach × inclusion benefit ÷ effort. Ties go to accessibility and inclusion.
  5. BuildA pull request that passes tests, the parity check and accessibility checks, with docs changed in the same request.
  6. ReleaseMerging rebuilds and publishes the portal. A version tag makes a GitHub Release with notes, a source zip and the offline portal, and opens an inclusion review. Commits that say "Closes #n" close the issue. With Confluence connected, the docs are published there too.
  7. Tell peopleA changelog entry, the What's new panel, the GitHub Release (people who watch the repository for releases are notified) and a note to the networks.

GitHub, Jira and Confluence

Status: GitHub is live: issues, milestones, discussions, releases, Actions and Pages all run. The Jira and Confluence workflows run as dry runs until an owner adds their secrets (repository Settings, Secrets and variables, Actions); they log what they would do, so nothing breaks before then.

Moderation and contributions

  • Everything is checked before it's public: no personal data, no named individuals without consent, accurate links, plain English, and nothing that exposes an organisation's unpublished problems without its agreement.
  • Moderators publish, ask for changes or decline within 10 working days, and always give a reason.
  • Contributions are under the Open Government Licence v3.0 unless the contributor chooses another open licence. Credit goes to the organisation, or stays anonymous.
  • Survey results are published only as totals, with counts under 5 hidden. Free text is never published without moderation.

How we'll know it's working

Reach

Organisations using the Commons, by type and nation, from opt-in surveys. We don't track people.

Outcomes

Critical assets with a measured baseline; issues resolved within their timescale.

Service

Time from request to first answer; commissions completed; open accessibility issues and their age.

Inclusion

Share of contributions from outside central government, and from each nation.
